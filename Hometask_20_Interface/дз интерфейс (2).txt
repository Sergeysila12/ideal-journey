Задача 1: «Система управления виртуальной библиотекой»
Постановка задачи:
Вам необходимо разработать систему для управления электронными ресурсами библиотеки. Система должна работать с различными типами документов: Книги, Журналы, Статьи. Каждый документ имеет уникальный идентификатор (ISBN для книг, ISSN для журналов, произвольный UUID для статей), название, год издания и список авторов.

Требования к реализации:

Иерархия классов: Создайте иерархию классов с использованием наследования. Базовый класс Document должен содержать общие поля и виртуальные методы. Производные классы Book, Magazine, Article добавляют специфичные для себя поля (например, для журнала — номер выпуска).

Создайте класс Library, который будет хранить словарь с документами и организовывать доступ к нему

STL Контейнеры: Используйте контейнер std::map или std::unordered_map для хранения всей коллекции документов. Ключом должен быть уникальный идентификатор документа (строкового типа).

Умные указатели: Все документы должны храниться в контейнере внутри std::unique_ptr<Document>. Продемонстрируйте передачу владения этих указателей в функцию добавления документа в библиотеку.

Обработка исключений:

Создайте собственный класс исключения LibraryException, унаследованный от std::exception, с информативным сообщением.

Реализуйте проверку на дубликат идентификатора при добавлении документа. При попытке добавить документ с уже существующим ID должно генерироваться исключение.

Реализуйте метод borrowDocument(const std::string& id), который меняет статус документа на "взятый". Если документ уже взят или не найден, генерируйте соответствующее исключение.

Полиморфизм: Реализуйте виртуальный метод void printDescription() const, который по-разному выводит информацию о документе в зависимости от его конкретного типа.





Задача 2: «Симулятор управления умным домом»
Постановка задачи:
Разработайте систему управления устройствами в умном доме. Устройства могут быть разными: Умная лампочка (SmartLight), Термостат (Thermostat), Датчик движения (MotionSensor). Все устройства можно включить или выключить, но делают они это по-разному.

Требования к реализации:

Интерфейсы и Абстракция: Создайте абстрактный базовый класс Device с чистыми виртуальными методами void turnOn(), void turnOff() и виртуальным деструктором. От этого класса наследуйте конкретные реализации устройств.

Умные указатели и полиморфизм: В классе SmartHome создайте контейнер std::vector<std::shared_ptr<Device>> для хранения всех зарегистрированных устройств. Продемонстрируйте, что различные устройства обрабатываются единообразно через указатель на базовый класс.

Обработка исключений: Реализуйте метод Device& getDevice(const std::string& id) для поиска устройства по ID. Если устройство не найдено, метод должен генерировать исключение std::out_of_range с соответствующим сообщением.

STL Алгоритмы: Реализуйте метод void turnOnAllDevices(), который включает все устройства, используя алгоритм std::for_each.

Копирование и перемещение: Запретите копирование класса SmartHome (используя = delete), но реализуйте корректное перемещение (конструктор и оператор перемещения), при котором владение вектором устройств передается новому объекту.





Задача 3: «Система бронирования отеля»
Постановка задачи:
Создайте систему обработки броней для небольшого отеля. В отеле есть номера разных категорий: Стандарт, Люкс, Апартаменты. Каждый номер имеет уникальный номер, цену за ночь и статус (свободен, занят, на уборке).

Требования к реализации:

Композиция и Агрегация: Создайте класс Room. Создайте класс Reservation, который агрегирует Room (через указатель или ссылку) и содержит даты заезда/выезда, данные гостя.

STL Контейнеры: Используйте std::vector<std::unique_ptr<Reservation>> для хранения всех броней и std::map<int, Room> для хранения всех номеров (ключ — номер комнаты).

Умные указатели: Используйте std::unique_ptr для владения объектами бронирований. Продемонстрируйте создание и добавление новой брони в вектор.

Обработка исключений:

Реализуйте проверку на доступность номера на запрашиваемые даты. При конфликте бронирования генерируйте исключение ReservationException.

Проверяйте корректность дат (дата выезда не может быть раньше даты заезда).

Перегрузка операторов: Перегрузите оператор вывода в поток (<<) для классов Room и Reservation для удобного отображения информации.

#include <iostream>

//Интерфейс - класс, который содержит только
//чистые вртуальные методы
//не должен содержать поля и конструкторы

//Множественное наследование от интерфейсов
//(реализация или имплиментация) допустимы

//В c++ не определено понятие интерфейсов
//поэтому они считаются абстрактными классами
//Интерейсы принято помечать буквой I в начале названия

class IMove
{
public:
    virtual void move() = 0;
};

class Player : public IMove
{
public:
    virtual void move() override
    {
        std::cout << "Я бегу";
    }
};

//ООП - подход при котором всё состоит из объектов
//1) Инкасуляция
//объединение данных и методов работы с ними
//сокрытие, один из аспектов инкапсуляции,
//который говорит, что поля должны быть недоступны
//извне
//2) Наследование
//одна сущность может получить характеристики от другой
//класс-родитель обобщает потомков
//ромбовидное или алмазное наследование 
// (примеры того, почему муножественное наследование 
// это проблема)
//3) Полиморфизм
//это явление при котором, один класс может работать
//и в контексте самого себя и в контексте родителя
//4) Абстракция
//Обобщение через абстрактные классы, которые 
// не существуют как отдельные объекты, а нужны
// исключительно для обобщения
// абстрактные классы не имеют объектов
// имеют чистые виртуальные методы
// интерфейс это тот же абстрактный класс, 
// но без полей, конструкторов и реализованных методов

//конструкторы (по-умолчанию, с параметрами,
// копирования, перемещения)
//деструктор
//сеттеры, геттеры
//константные методы
//виртуальные методы (переопределяемые)
//чистые виртуальные методы
//SOLID
//S - принцип единственной ответственности
//один класс решает одну задачу
//лучше много простых классов, чем несколько сложных
//O - принцип открытости\закрытости
//классы должны быть открыты для расширения, 
//но закрыты для изменения
//L (LSP) - принцип подстановки Лисков
//функция должна работать с подтипами базового типа
//не зная об этом
//I - принцип разделения интерфейсов
//каждому потребителю свой интерфейс
//каждый интерфейс под одну сферу задач
//D - принцип инверсии зависимостей
//уровень абстракции не может повышаться,
// он может сохраняться или понимжаться

//контейнеры stl
//умные указатели stl
